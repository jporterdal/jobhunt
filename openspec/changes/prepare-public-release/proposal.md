## Why

The code is ready to show, but the repository isn't. An audit of all 48 commits and the working tree found the user's own data throughout, used as test data and spec examples: the CV's degrees, institutions, course numbers, teaching terms, a paper's DOI, a thesis handle, the GitHub handle, location and availability date. It also found the real job-site posting IDs, posting titles, salary lines and employers the user looked at, and the commit author's institutional email. This change's own artifacts describe these only by category: the concrete values live in a private, ignored file (see design, D3). A database copy holding CVs and a cover letter sits untracked and not ignored (`data.bak-2026-10-15/`), one `git add -A` away from a commit. Recruiters are the expected readers of a public repo, so it has to show nothing about the user's job search and still read as strong engineering work. Separately, the user keeps the site-specific capture parser private: the public repo must neither publish it nor mention it.

## What Changes

- **A fresh public repository.** The current repo, with its history, stays private and is never made public. The public repo starts from one sanitized snapshot, so nothing from old commits can leak. After release, development continues in the public repo.
- **Nothing about the private capture parser.** The public tree, its history and this change's own artifacts never name the job site the parser reads, its domain, its page markers or the capture workflow. Specs and archived changes that are only about the parser move to the private parser repository; the rest are rewritten in source-neutral terms. The site's terms go in the private term file, so the privacy check enforces this without the public code naming them. Splitting out the parser itself is a separate change, `separate-capture-parser`, which comes first (see Impact).
- **No real name in committed files.** Commits are authored under the GitHub handle with a GitHub noreply address. LICENSE, README and `pyproject.toml` name no person in the first public commits; the user adds attribution later.
- **Fictional data everywhere.** Every test, fixture, spec scenario, archived change and code comment that quotes the user's CV, postings, employers, job IDs, salaries or links uses invented values instead (one fictional persona and invented companies, consistent across files). Measurement write-ups keep their numbers but name postings by label ("posting A"), not by ID or title.
- **A privacy check, `jobhunt privacy-check`.** It builds a list of personal values from the local database (profile details, records, lines, sources, highlights, document names, posting IDs, titles and companies, companies, contacts, notes) plus an optional private term file. It then scans every tracked file and, with `--history`, every commit's files, messages and author fields. It also checks patterns that need no database: long numeric posting IDs, emails and phone numbers outside reserved example ranges, home-directory paths, and document or database files outside the synthetic fixtures. It exits non-zero on any finding. A pre-commit hook runs it locally, and CI runs the pattern-only part.
- **Harder ignore rules.** Backups, databases, office documents, saved pages and editor-local settings are ignored by pattern, not by single filenames.
- **A demo database, `jobhunt demo`.** It creates a synthetic database for the fictional persona, with postings (brought in through the app's public, source-neutral import), triage, an application, a profile, model suggestions, links and a saved CV. It goes through the app's own writers, uses scripted model answers, and needs no Ollama. Anyone can try the app in a minute, and every screenshot is taken from it.
- **Recruiter-facing presentation.** A README covering the pitch, screenshots, quick start, architecture, design decisions, how measurement works, known limitations, a "Getting postings in" section on the public import format, and a "How this was built" section. That section describes the spec-driven, AI-assisted workflow openly: what the user decided and measured, and what the model wrote. Also docs for architecture and measurement methodology, a LICENSE with no personal name, a SECURITY note (local only, no authentication), `pyproject.toml` metadata, ruff linting, and GitHub Actions CI (pytest on SQLite and Postgres across the supported Pythons, lint, pattern privacy check).
- **Stray-file cleanup.** Root-level saved pages (`copy.html`, `copy2.htm`), `Zone.Identifier` files and the untracked `FUTURE_CHANGE.md` stay out of the public tree. Its useful items become a scrubbed `ROADMAP.md`.

## Capabilities

### New Capabilities
- `release-privacy`: the privacy check, which finds personal values and patterns in tracked files and git history, and the rules a public tree must pass.
- `demo-data`: creating a synthetic, self-contained demo database that exercises every page without a model server.

### Modified Capabilities
None. Accepted specs whose scenarios quote real data or name the job site (`skill-profile`, `profile-extraction`, `application-tracking`, `posting-storage`, `posting-enrichment`, `posting-triage`, `recommendations`, `web-interface`, and `tailored-cv` once archived) get fictional example values and source-neutral wording in place. `posting-extraction` left the public repo with the parser (`separate-capture-parser`); `capture-import` stayed, rewritten in source-neutral terms, and holds the public import format. The edited specs' requirements don't change, so no deltas are written (see design, D4).

## Impact

- **New code:** `src/jobhunt/privacy.py` (term collection and scanning, no Flask), `src/jobhunt/demo/` (persona, synthetic postings and scripted model answers as package data, seeding), and `privacy-check` and `demo` subcommands in `cli.py`.
- **Edited, values and wording only:** about 15 test modules (`profile_0007.py`, `test_cv_pipeline.py`, `test_upgrade_profile.py`, `test_cvdoc.py`, `test_profile.py`, `test_documents.py`, `test_companies.py`, `test_profile_suggestions.py`, `test_userdata.py`, `test_tailor.py`, `test_web_cvs.py`, and more), 9 accepted specs, the archived and active change folders that stay public, a few code comments (`tailor.py`, `links.py`), `CLAUDE.md` and `.claude/`.
- **New files:** `README.md`, `docs/`, `LICENSE`, `SECURITY.md`, `ROADMAP.md`, `.github/workflows/ci.yml`, `.pre-commit-config.yaml`, and ruff settings in `pyproject.toml`.
- **Dependencies:** `ruff` and `pre-commit` join the `dev` extra. No runtime dependency is added.
- **Ordering:** `generate-tailored-cv` is archived first. Its last tasks use the user's real profile, and its specs must be in `openspec/specs/` before they are scrubbed. `separate-capture-parser` is archived next (done 2026-10-21). It makes the public app source-neutral, with a public import format and a plug-in point for capture parsers. It also moves the parser, its fixtures and tests, its extraction spec and its golden tests over private captures to a private repository. This change depends on that import format for the demo and removes whatever mentions the move leaves behind.
- **Untouched:** the private repo and its history, the private parser repository, `data/`, the user's database and documents.
